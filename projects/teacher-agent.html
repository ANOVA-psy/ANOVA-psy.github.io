中学教师教学评估与改进智能体Teaching Evaluation & Improvement Agent

教研里最耗时的活是听一节课、写一段评语。这个项目把它拆成几步交给模型跑：材料进去，带证据的评价和能动手改的建议出来。 The slowest part of lesson review is watching a lesson and writing feedback. This project splits it into steps a model can run: materials in, evidence-backed evaluation and actionable suggestions out.

问题出在哪Where the problem is

中学教研里，一节课的评课往往依赖教研员与骨干教师的经验：听课、记要点、写评语、给改进方向。这件事有三个麻烦——标准难统一、反馈周期长、经验难沉淀。 Lesson review in secondary schools runs on the experience of senior teachers: watch, take notes, write feedback, suggest improvements. Three problems follow — standards drift between reviewers, feedback arrives late, and knowledge never accumulates.

大模型看起来适合做这件事，但直接"让模型评一节课"会得到一段正确而无用的文字。真正要做的是把评价拆成维度、把判断写成规则、把输出锁进格式——这样结果才可比较、可复核。 An LLM seems like a fit — but "just ask the model to review this lesson" produces fluent, useless prose. The actual work is decomposing the judgement into dimensions, writing the criteria as rules, and constraining the output format so results are comparable and reviewable.

使用者分两类：教师需要看得懂、改得动的建议；教研员与研究者需要在同一套编码体系下汇总多节课、做横向比较。 Two audiences: teachers need suggestions they can act on; researchers need to aggregate lessons under one coding scheme and compare across them.

My Contribution

我负责的部分What I owned

这个项目由课题组共同完成，我主要负责把"评课"这件事翻译成模型能执行的任务。A team effort; my part was translating "lesson review" into a task a model can execute.

任务拆解Task decomposition

从一句话需求到可执行步骤From a vague ask to executable steps

把"评价一节课"拆成材料解析、维度打分、证据定位、建议生成四个可分别校验的环节，每一步都有明确的输入与输出。Broke "evaluate a lesson" into parsing, dimension scoring, evidence grounding and suggestion generation — each with defined inputs and outputs.

Prompt 体系Prompt system

维度 · 规则 · 格式Dimensions · rules · format

设计三层结构：评价维度定义（评什么）、判定规则（什么算好）、输出格式（怎么呈现），并沉淀成可复用的评估类模板。A three-layer structure — what is evaluated, what counts as good, and how it is presented — distilled into a reusable evaluation template.

多轮对照迭代Iterative comparison

一致性优先于"写得好"Consistency over eloquence

用同一批材料反复跑、比对输出，找出模型跑偏的位置，再回改规则而不是堆修饰词；目标是同一节课两次评价的结论不打架。Ran the same materials repeatedly and compared outputs, fixing the rules where the model drifted rather than adding adjectives — aiming for stable conclusions across runs.

与教研流程对齐Aligning with practice

按真实使用调流程Adjusted by real use

根据实际使用反馈调整提示词与任务顺序：先给结论还是先给证据、建议写多细、哪些话不该说，都在线框阶段反复改过。Prompt wording and task order were revised against real usage: conclusion first or evidence first, how granular suggestions should be, what the system should not say.

Workflow

系统怎么走完一节课How one lesson flows through

下面这条链路对应线框里的页面顺序，也是我和团队讨论任务边界时用的同一张图。This chain matches the page order in the wireframes — the same diagram used to scope the work with the team.

01
提交材料Submit materials
教学设计、课堂实录、作业或反思，可单节提交也可批量导入。Lesson plan, recording, assignments or reflection — single or batch.
02
结构化解析Parse
把非结构化材料切成可定位的片段，作为后续判断的证据来源。Split unstructured materials into locatable segments that later judgements can cite.
03
多维评价Evaluate
按预设维度与判定规则逐项打分，要求给出对应证据。Score each dimension against written rules, with evidence required.
04
生成报告Report
把分数与证据组织成教师能读的报告，而不是一堆术语。Assemble scores and evidence into a report a teacher can read.
05
改进与沉淀Improve & accumulate
输出可执行的改课建议，并把课例归入教研主题供后续比较。Output actionable changes and file the lesson under a research theme for later comparison.
Try it

走一遍评课流程Walk through a review

选一节课，看它怎么被拆成材料解析、维度评分、证据定位、改进建议四步。每个分数都能点开，看看它对回的是实录里哪个时间点。 Pick a lesson and watch it move through four steps: parsing, scoring, evidence, suggestions. Every score opens up to the timestamp it came from.

这是设计稿，不是线上系统：A design demo, not a running system: 三节课例、分数、证据与建议都是预置的示例内容，点「开始评估」不会调用任何模型，也不保存任何东西。它演示的是报告长什么样、评价怎么落到证据上——这两件事是能公开的设计部分。 The three lessons, the scores, the evidence and the suggestions are all preset sample content. Nothing is sent to a model and nothing is stored. What the demo shows is the report format and how a score gets pinned to evidence — the part of the design that can be public.
