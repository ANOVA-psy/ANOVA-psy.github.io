界面 / Screens

入口 · 阶段选择

被试只填编号与基本信息，然后选本次走哪个阶段。三条路径互不交叉，实验者不需要在旁边解释下一步点哪里。

静态截图。真实系统中，点进任一阶段才会加载该阶段的刺激与流程。

功能一 · 噪音抗干扰

后测结果页：上方四格是编号、正确率、平均反应时与试次总数，下面是 SNR 与正确率的 S 型拟合，虚线标出 75% 判准对应的阈值。

图中阈值 −5.0 dB 与 R² = 0.89 由曲线拟合直接给出，不是人工标注。

功能二 · 视觉整合

同一张图里放两条曲线：清晰口型与模糊口型。两条曲线在横轴上的间距就是视觉增益，也就是"看口型"实际帮了多少。

增益 4.0 dB 已到量表上限，对应“视觉代偿”维度满分。

功能三 · 异步校准

横轴是声音与画面的时间差（SOA），负值表示视觉领先。阴影区是仍能整合为单一事件的时窗，宽度由 75% 判准截出的上下边界相减得到。

图中时窗宽度 288 ms：111 ms 超前 + 177 ms 滞后。

功能四 · 注意定位

把单说话人与双说话人的曲线画在一起，两条曲线之间的距离就是"有人在旁边说话"带来的干扰成本，右侧箭头把它标成 dB 差值。

单任务阈值 −4.9 dB、双任务 −0.7 dB，差 4.1 dB。

系统结构

平台不是纯前端项目：被试端负责流程与音频调度，服务端负责配置与数据落盘。这也解释了为什么它无法直接托管成静态网站。

被试端 (index / result / history)

  • app.js · 流程控制
  • modules/module1-4.js · 训练逻辑
  • core/StaircaseController.js · 阶梯
  • audioProcessor.js · 毫秒级音画调度
  • psychometric.js · 曲线拟合
  • dataManager.js · 存取与导出

管理端 (admin)

  • adminSettings.js · 参数配置
  • adaptiveEngine.js · 起点推荐
  • constants.js · 全局常量

存储

  • localStorage（前端缓存）
  • server.js · Express API
  • data/experiment_history.json + config/settings/{subjectId}.json

以上为源码目录结构的摘要，用于说明各模块职责；完整实现见 GitHub 仓库。
